**稼働中。** 毎朝08:00（`Asia/Tokyo`）にGitHub Actionsのスケジュールが走り、条件に合うconnpassイベントの
一覧がDiscordへ1通届く。画面も永続ストアも持たない。2026-08-23にsecretsを登録して実運用に入り、

**構成**（`adr/0001`・`0003`・`0005`）: 興味条件はリポジトリ内のYAML。取得→絞り込み→算出→整形→配信の
5段で、外部I/Oは取得（connpass API v2）と配信（Discord Incoming Webhook）だけ。`NotifierPort` が
配信先を差し替え可能にしている。

**拾い方は二軸**（`adr/0005`）。1つのプロファイルで両方は使えない——`publish_ymd` と `ymd` を同一
リクエストへ渡したときの結合の意味が一次情報に無いため、機械的に禁じている。

| 軸 | 指定 | 現在の設定 |
|---|---|---|
| 新着軸 | `publishedWithinDays` | 昨日公開されたもの。話題別に5本（AI/LLM・アーキテクチャ・クラウド・コンテナ/IaC・言語）、いずれもonline |
| リード軸 | `startsInDays` + `windowDays` | 7〜8日後に開催。全キーワードを1本にまとめ、online |
| 地元 | `windowDays` のみ | `toyama` を14日分、**キーワード無しで全件** |

**届く形**: Discord Embed。日付ごとの見出し、タイトルはリンク、時刻・場所・主催・参加者数・残席を1行、
主催者の1行説明（`catch`）を斜体で1行。イベント間と日付の間は空行で区切る。**Embedは見出し記法
`##`・小文字記法 `-#` を描画しない**ため、区切りに使えるのは空白だけである。6,000文字を超えた場合だけ
完全一覧を同じメッセージへ添付する（`adr/0003`）。

**地域を公開リポジトリの興味条件に書く判断は `adr/0004`**——地名を使ってよいのは興味条件の**値**だけで、
リポジトリ名・プロジェクト名・ブランチ名には使わない。

**契約**: `daily-digest-contract.yaml` v0.3.0-draft、`daily-digest-test-support.yaml` v0.3、
`daily-digest.feature` の CSR-D-01〜10（全シナリオ実装済み。`@pending-implementation` は残っていない）。

## 実運用で分かったこと（2026-08-23）

**初日の7日窓は破綻した**——78件・約9,900文字でEmbedの6,000文字上限を超え、添付テキストに退避して
Markdownとして描画されなかった。しかも翌朝は78件中73件が同じものだった。二軸へ組み替えた結果、
**9件・約1,800文字**になり、Embedとして描画された。

**新着軸は定期開催に偏る**。9件中4件がもくもく会だった。毎週ページが作られる定期開催は「昨日公開」に
必ず入る一方、大物（792人の講演等）は数週間前に告知済みなので新着軸には二度と現れない。大物を拾う
経路はリード軸だけであり、当たる曜日に依存する——1日だけだと日曜に当たった日は2件しか返らなかった。
リード軸を2日に広げてある。**3日にすると平日が2日入って6,000文字を超える計算**なので、そこで止めた。

**1行説明は効いている**。「0からのClaudeCodeによるAIエージェント入門セミナー」の説明が「実務に直結する
データ分析の基礎を習得」であり、タイトルだけなら開いていたものを切り捨てられる。

**地元プロファイルにキーワードを付けなかった判断も効いている**。富山デザイン勉強会は、どの技術
キーワードでも拾えなかった。

## 実測した外部の事実（一次情報へ未昇格）

**`connpass-api-v2-facts.md` はこれらを持っていない。** 本ファイルは上書き運用なので、放置すると
git履歴の中にしか残らなくなる。昇格が宿題である。

- **`ymd` の複数値はOR結合**。2026-08-22の114件と2026-08-28の60件は重複0件で、反復指定・カンマ指定とも
  和集合と同じ174件だった。現在の反復指定実装を維持する
- **API v2 はイベントに `prefecture` を返さない**。そのため「オンライン開催かどうか」は
  `prefectures: ['online']` 単独のプロファイルから来たかどうかで判定している
- **`keyword`(AND) と `keyword_or`(OR) を同一リクエストへ渡したときの結合の意味は不明**。現在の条件は
  プロファイルごとにORグループ1つだけを使い、この空白を踏まない形にしてある。「AWSの深い話だけ」の
  ように話題×深さで絞るには、この結合の実測が要る
- **Discordのフォーラムチャンネル向けWebhookは `thread_name` または `thread_id` が必須**。現在の契約の
  対象外なので、通常テキストチャンネルを使う
