# ADR-0006: 空き枠は「予約可能な空き」だけを返す（最小予約時間未満の隙間を除外する）

- 日付: 2026-07-16
- 状態: 承認済み（人間裁定 2026-07-16。契約RSV-Aの承認に随伴）
- 置き換え対象: なし

## 文脈

スライスRSV-Aの契約ドラフト（空き枠を確認できる）をレビューした人間が、最小予約時間（30分、RSV-C-05のTOO_SHORT）との相互作用を指摘した。予約と予約の間に30分未満の隙間があると、カレンダー上は空いているが誰も予約できない。ドラフトの初版はこの隙間も「空いている時間帯」として返しており、当該挙動は未定義に近い状態だった（既存6シナリオの隙間は全て30分以上のため、間違ってはいないが穴が残る）。FR-005（別々に読むと見えない契約の穴）と同型の見落とし。

## 決定

空き枠クエリは「予約可能な空き」のみを返す。最小予約時間（30分）に満たない連続空きは、availableSlotsに含めない。最小予約時間ルールはドメインの1箇所（RSV-C-05を担うロジック）に保ち、読み取り側はそれを参照する。

## 検討した代替案

- 案A: 生の空き時間を返し、最小時間のフィルタはクライアントに委ねる / 不採用: 最小予約時間というサーバ側の業務知識をクライアントと二重管理することになる（architectがレスポンス形の解釈ポイントで占有時間返却案を退けたのと同じ理由）。かつ目的文「予約する前に知る」に対して、予約できない枠を空きと答えるのは誤誘導
- 案B: このスライスでは決めず未定義のまま送る / 不採用: FR-005の再演。相互作用は契約時に潰す

## 帰結

- シナリオRSV-A-05（最小予約時間に満たない隙間は空き枠に現れない）を契約に追加。以降のIDを繰り上げ（キャンセル→A-06、部屋なし→A-07）
- availableSlotsの各区間は「最小予約時間以上の連続空き」であることが不変条件になる
- 最小予約時間の値（30分）をクライアントにどう見せるかは未解決の論点（別途検討）。本ADRは空き枠の内容を定めるもので、ルール値の露出は範囲外
