# ADR-0005: 予約をキャンセルできるのは予約した本人のみとする

- 日付: 2026-07-15
- 状態: 承認済み（人間裁定 2026-07-15。契約RSV-Kの承認に随伴）
- 置き換え対象: なし（ADR-0003「予約者の資格・認証ルールはこのスライスでは持たない」の適用範囲を、キャンセル操作について限定する）

## 文脈

スライスRSV-Kの契約ドラフトで、architectが「キャンセルは本人限定か」を解釈ポイントとして提示。ドラフトはADR-0003（予約者資格ルールを持たない）の踏襲として限定なし案を採っていたが、人間は本人のみと裁定した。予約の作成は誰でもできる（ADR-0003）が、既存の予約を消す操作は他人の資源への干渉であり、対称に扱わない。

## 決定

キャンセルは予約した本人のみ実行できる。キャンセルリクエストは実行者のreserverIdを必須で受け取り、予約のreserverIdと一致しない場合は拒否する（403 / NOT_RESERVER）。本格的な認証基盤は導入しない（reserverIdの自己申告ベース。認証は将来の別スライス）。

## 検討した代替案

- 案A: 限定しない（architectドラフト案） / 不採用の理由: 予約IDを知っていれば誰でも他人の予約を消せるのは、業務常識として受け入れがたい。「作成は開放・削除系は本人のみ」の非対称は妥当

## 帰結

- シナリオRSV-K-02（他人の予約はキャンセルできない）と理由コードNOT_RESERVERが契約に入る
- Given「予約が存在する」は持ち主を明示する形（予約者"佐藤"の予約）が必要になり、既存stepの語彙が1つ増える
- 同時に裁定された契約詳細3点は契約本文がSSOTとして保持する: 15分前ちょうどはキャンセル可 / 二重キャンセルは409エラー / 成功応答は200+キャンセル後の予約内容（cancelledAt付き）
- reserverIdは自己申告のため、なりすましは防げない。認証を入れるスライスでこのADRを拡張または置き換える
