# デザインブリーフ — 会議室予約Webアプリ

個人情報・機密情報は書いていない。会議室名・ID・日付・予約者名はすべて架空のプレースホルダを使う
（会議室A/room-a、佐藤、鈴木、2026-07-14等）。

## 目的

会議室予約Webアプリの中核体験——予約者が会議室を予約するために必要な一連の画面/フロー——を設計してほしい。

## 対象ユースケース

予約者（社員に限らない一般利用者。認証はなく、名前やIDを自己申告する）が、次を行き来しながら行う
一体の体験として設計してほしい:
- 会議室の空き状況を知る
- 空いている時間帯に予約する
- 自分の予約を確認し、不要なものをキャンセルする

## ドメインルール（最小限）

- 会議室ごとに営業時間（例: 会議室Aは09:00〜18:00）と定員（例: 6人）が決まっている
- 予約は最小30分から。同じ会議室の同じ時間帯を複数の予約が重ねて占有することはできない
- キャンセルできるのは予約した本人のみ、かつ開始15分前まで
- 予約者はreserverId（自由文字列）を自己申告するだけで、認証・資格チェックは無い

## 現在のバックエンドAPI

- `POST /reservations`（roomId, reserverId, date, startTime, endTime, attendeeCount）→ 予約を作成する
- `POST /reservations/{id}/cancel`（reserverId）→ 予約をキャンセルする
- `GET /rooms/{roomId}/availability?date=YYYY-MM-DD` → 指定日の空いている時間帯一覧を返す
- `GET /rooms/{roomId}/rules` → 営業時間・定員・最小予約時間を返す

会議室の一覧を取得するAPI、予約の一覧・自分の予約を参照するAPIは現状無い。UXとして必要なら、遠慮なく
指摘してほしい。

## 解決したい問題（今の試作の不満）

現行の試作画面は次の理由で実用に耐えない:
1. 毎回「会議室＋日付を指定→ボタン」でないと空きが見えないのは手間。もっと低摩擦で見たい
2. 空きを「09:00–10:00」のような時刻の羅列で見せるのが非直感的。1日のタイムライン/カレンダー上に
   空き・埋まりを帯で見せる等、分かりやすい可視化がほしい
3. 「今の予約状況」（誰がいつ押さえているか、自分が何を予約しているか）が見えない
4. 空き枠をクリックして予約する、のような直接操作がしたい

## 制約からの解放

既存のバックエンドAPIの形に縛られなくてよい。予約者にとって最も自然な体験を起点に、自由に発想して
設計してほしい。画面の数・構成もこちらでは指定しない。

## 技術前提

実装時はTypeScript + React + Vite。UIはshadcn/uiの視覚言語・意匠に倣う。

## 成果物

**React + TypeScript のコンポーネント（TSX）**として出力してほしい:
- shadcn/uiのコンポーネントを`@/components/ui/...`からimportしてよい。利用可能: card, button, badge,
  dialog, tabs, input, label, select, popover, calendar, sheet, scroll-area, sonner(toast), separator。
  アイコンはlucide-react
- ダミーデータを内蔵し、プロジェクトに置いて表示した瞬間に画面が見えること。空き枠クリック→予約、
  自分の予約の表示、キャンセルなど主要な操作はモックで動くとよい
- バックエンドAPIは呼ばず、内蔵のダミーデータで完結させること
- 単一ファイル、または少数ファイルにまとめること
- 設計にあたって前提とした、または欲しくなった新規APIがあれば、末尾に簡潔に列挙する
