# デザインブリーフ — 会議室予約Webアプリ 中核体験（試行2・独立作成）

> designer(a)の成果物。雛形: meta/templates/design-brief.md。外部AIへの発注書であり、UI/UXの発案は
> ここでは行わない。個人情報・機密情報は書かない（プレースホルダのみ）。

## 目的
会議室予約Webアプリの中核体験――空き状況を知る、空いている時間帯に予約する、自分の予約を確認して
不要なものをキャンセルする――を一気通貫で行える画面を設計してほしい。

## 対象ユースケース
利用者（社内の会議室予約者）が次の3つを行いたい:
1. ある会議室が、指定した日にいつ空いているかを知りたい
2. 空いている時間帯を見つけたら、その場で予約したい
3. 自分が既に入れた予約の一覧を確認し、不要になったものを取り消したい

利用者は特定の会議室名を最初から知っている前提で構わない（一覧から選ぶ手段は現状のバックエンドに
無い。下記「現在のバックエンドAPI」参照）。認証の仕組みは無く、利用者は自分の名前・IDを都度自己申告
する運用を前提にしてよい。

## ドメインルール（最小限）
- 予約は「会議室×時間帯」の単位で排他的。同じ会議室の同じ時間帯を二重に予約することはできない
- 時間帯は半開区間。ある予約の終了時刻ちょうどに次の予約を始めることはできる（隙間なく連続可）
- 予約は最短30分から。会議室ごとに営業時間と定員がある
- 予約をキャンセルできるのは予約した本人のみ、かつ開始15分前まで（15分前ちょうどはまだ可能）
- 一度キャンセルした予約は復活しない。キャンセルされた時間帯は他の人が予約し直せる

## 現在のバックエンドAPI（列挙）
- `GET /rooms/{roomId}/availability?date=YYYY-MM-DD` — 指定会議室・指定日の空いている時間帯一覧
- `GET /rooms/{roomId}/rules` — 指定会議室の営業時間・定員・最小予約時間（30分固定）
- `POST /reservations` — 予約作成（会議室ID・予約者ID・日付・開始/終了時刻・人数を送る。成功で予約IDが返る）
- `POST /reservations/{reservationId}/cancel` — 予約キャンセル（予約者IDを送る。成功でキャンセル後の内容が返る）

**上記に無いもの**: 会議室を一覧するAPI、特定の予約者の予約一覧を取得するAPI、特定の予約1件の詳細を
IDだけで取得するAPIは今のところ存在しない。設計上「これが無いと成立しない」と感じた操作があれば、
成果物の中で明示的に指摘してほしい（後で私たちが実際にAPIを追加するかどうかを検討する材料にする）。

## 解決したい問題（任意）
- 会議室名・予約ID・利用者IDのような識別子を、利用者に手入力・記憶させる場面はできる限り減らしたい
- 「予約する前に空きを見る」「予約後に自分の予約を見直す」が、別々の作業ではなく地続きの体験になって
  ほしい（空きを見た流れでそのまま予約できる、予約した流れでそのまま自分の予約一覧に反映されて見える）

## 制約からの解放
既存のAPIの形（会議室ID・日付を都度指定する等）に縛られる必要はない。利用者にとって理想的な体験を
自由に描いてよい。理想と現在のAPIとのギャップは、この後の私たちの作業（契約との突き合わせ）で吸収する。

## 技術前提
- TypeScript + React 19 + Vite + Tailwind CSS v4
- shadcn/ui（Radix UIベース）を採用済み。次のコンポーネントが `@/components/ui/` に導入済みで
  そのままimportできる: button, card, badge, tabs, input, label, select, popover, scroll-area,
  sonner（トースト通知）, separator, dialog, calendar, sheet
- 追加ライブラリとして `lucide-react`（アイコン）, `date-fns`, `react-day-picker` が利用可能
- パスエイリアス `@/` がプロジェクトルートの `src/` を指す（例: `@/components/ui/button`, `@/lib/utils`）

  `npm run dev` で描画できる、shadcn/uiベースのTSXコードそのものを返してほしい

  分けても構わない（同一ファイル内で構わない）
- 実際のバックエンドは呼ばない。会議室・空き時間帯・自分の予約一覧は、コンポーネント内にダミーデータ
  として埋め込み、propsや外部設定なしでそのまま表示が成立するようにしてほしい（会議室名・予約者名等は
  仮の名前で構わない。実在の個人名は使わないこと）
